# WorkBuddy 模型选择恢复

本次修复补齐旧版已有、Qwork 首轮迁移遗漏的模型选择链路。

- 设置卡片读取原生 WorkBuddy 已配置的自定义模型，仅返回模型 ID 和显示名称。
- 支持“跟随 CLI 默认模型”和选择已配置且支持工具调用的模型。
- Qwork 只保存模型 ID；密钥与服务地址仍来自 WorkBuddy 原生配置，不进入渲染器或 Qwork 设置文件。
- 原生配置检测、连接测试、单聊与群聊调用均使用同一选择。
- 切换模型禁止在任务运行中进行；当前调用开始时捕获选择。
- 连接测试通过后更新卡片；失败原因保留在对应卡片，避免一条通用提示无法定位。

原截图中的“需要登录”来自 CLI 认证错误的通用映射，不足以证明 WorkBuddy 桌面端退出登录。迁移版没有选择旧版使用的自定义模型时，会走独立 CLI 的默认认证路径；桌面端的登录或自定义模型不一定自动成为该路径的配置。

使用方法：设置 → WorkBuddy → 执行模型 → 选择原来使用的模型 → 保存模型 → 测试连接。

如果列表为空，请先在 WorkBuddy 原生应用中配置自定义模型并启用工具调用，再点击刷新。不要将 API 密钥粘贴到 Qwork 对话或 Issue 中。

验证：新增三项回归覆盖模型检测、模型配置转发、默认认证提示及自定义提供者错误；总计 29 项 Qwork 测试通过。没有擅自选择用户模型或发起新的真实 WorkBuddy 模型请求，具体连接仍需用户选定模型后确认。
